# 回归基线（开发侧文档）

本文件记录「用户可观察行为」的基线，供源码工程逐模块对齐时使用。它属于开发内部资料，不进入公开同步目录。

## 一、基线从哪来

可运行成品积累了 33 支行为探针（`tools/*-probe.mjs`）与 `tools/verify.mjs` 的结构断言。它们不看实现、只看可观察结果，因此正好可以当标尺：新版某个模块上线前，必须能用原探针或等价断言证明行为一致。

新版另有三层回归（见 `docs/PLATFORM.md` §九）：契约/边界（秒级）→ 模块行为 → 端到端探针。

## 三、验收规矩

1. **改完必须真跑那条执行路径**。语法检查、静态断言、编译通过都不算验证（历史上多次出现「断言全绿但接口稳定报错」）。
2. **旧版可运行成品保留在本地开发目录作为对照**，不进入公开同步目录；新版模块逐个对齐，不要求一次性全量迁移。
3. **每加一个模块**：补该模块的契约测试 + 对应行为探针，并在 `npm test` 里挂上。
4. **每改一条契约**：先跑 `npm run test:boundaries`，类型检查会列出所有受影响模块，逐个确认后再改实现。
5. 端到端探针在真实程序里用 CDP 驱动，断言可观察结果，不读内部变量。
6. **界面差异要量化，不靠肉眼**：项目根的 `.spec/` 里有抓取与对比脚本（`scenes.mjs` 抓成品、`newscenes.mjs` 抓新版、`measure.mjs` 逐区域比尺寸、`cmp*.mjs` 比配色与坐标）。它们只做开发对照，不进仓库。

### 回归分级（「改 E 只测 E」的适用边界）

模块化解耦的是**代码依赖**（`apps → features → engine → core → contracts` 单向、贡献点可插拔），不等于**运行时影响隔离**：所有功能共享同一块画布、同一份工程文档、同一个全局状态，探针也依赖 DOM 结构与选择器。因此回归按影响面分四级执行，而不是每次都跑全部专项：

| 级别 | 内容 | 成本 | 何时跑 |
| --- | --- | --- | --- |
| L1 | `npm test`（167 项纯逻辑单测，按包分文件）+ `test:types` + 边界检查 | < 1 分钟 | **任何改动都跑**——它便宜，且 core/engine 的纯函数改动只到这一级就够 |
| L2 | 模块专项探针（`.spec/*-check.mjs`，按功能域划分） | 每支 20~60 秒 | **只跑被改动影响的功能域**：改字幕列表跑 `list-move` / `fontsize-split`，改导出跑 `export-phases` / `export-e2e`，改字体跑 `font-check` / `fonts-preview-check`，改滑块跑 `range-snap-check`……不相关的专项不跑 |
| L3 | `smoke:desktop` 88 项全局冒烟 | 2~3 分钟 | **凡动到 UI / 画布 / 全局状态必跑**。历史教训：按钮类名改动曾级联弄挂预览、播放、拖时长、撤销、导出六项（11-12）；ASR 滑块挪位让冒烟找不到选择器；`canvas.toBlob` 的空闲任务饿死让导出在后台停摆——这些都不是「模块内」能测出来的 |
| L4 | 端到端（真实导出出片、ASR 识别、录音、大文件流式落盘） | 分钟级 | 只在动到那条链路（`media.ts` / `server.mjs` / 录音面板 / 渲染服务）时跑 |

结论：**纯 core / engine 算法改动可以只跑 L1 + 相关 L2**；但只要改动触及编辑器界面（组件、CSS、store、桥），L3 冒烟就是必要保险——它保护的不是某个模块，而是「所有模块共享的画布与状态」这条公共链路。实践中每轮的探针组合都是按影响面挑选的，从未有过「每次跑全部 20+ 支专项」的要求。

## 四、当前对齐进度

十个功能组都已按成品行为对齐：编辑器界面、双轨时间轴、按帧预览、音频与录音、语音转字幕、视频与字幕导出、文件 IO 与快捷键。边界检查 0 违规、168 项 Node 回归全绿、启动探针 11/11，桌面探针 88/88（含真实桌面窗口、播放链路、时间轴拖动/缩放/撤销、音频导入波形与分界、识别参数持久化、导出面板参数、方向键步进与末尾定位、查找替换、列表拆分合并与编辑开关、播放高亮、旧版工程导入、录音面板形态、字体目录与字形加载、End 停在卡片末端），另有 `.spec/ui-round-check.mjs` 26/26、`.spec/ui-round2-check.mjs` 23/23 专测界面默认值、字形效果、快捷键与插入不重叠；`.spec/round-fix-check.mjs` 16/16（全局动画一次统一、列表单条动画优先、移动下拉上移→左旋→右旋、字幕水平位置滑块随风格切换、字幕导出弹窗桥、>20MB 字体导入）；`.spec/fontsize-split-check.mjs` 14/14（列表拆分与时间轴切分后逐条改字号互不串位）；`.spec/fonts-preview-check.mjs` 13/13（导入字体真实加载、面板示例与悬停大预览按导入字体渲染、导入面板保存前实时预览）；`.spec/perf-stress-check.mjs` 7/7 与 `.spec/fonts-perf-check.mjs` 6/6（大体积复杂字形字体 + 数百条字幕长播帧率不恶化：时间轴播放头解耦、字幕列表行 memo、求值二分与缓存；⚠️ 文字位图缓存已按哥哥裁定于 11-17 回退删除——它引发吞字/闪烁，显示正确性优先于性能，长播帧率会恶化为已知且被接受的状态）；`.spec/stack-visibility-check.mjs` 13/13（屏幕适配每句按占比重新取景、25 字长句最后一个字不被裁掉、右旋竖排底部与新句基线对齐不割裂、历史句与当前句边缘锐度一致不模糊，红/蓝/绿像素分离断言）。⚠️ `.spec/fonts-fit-perf-check.mjs` 与 `.spec/srt-full-check.mjs` 的「帧率全程稳定」断言在位图缓存回退后**不再满足**（长播会逐渐变卡，为已知且被接受的取舍），保留探针仅作帧率观测。

界面的对齐方式是：启动成品 → 用 CDP 读真实 DOM、计算样式与坐标 → 逐区域重建 → 用 `.spec/measure.mjs` 逐项量化对齐。成品对照的 20 个区域尺寸如下（播放器宽 814 对 812，差 2px，来自高度锁定后的取整；当前布局的可调范围见下方条目）：

| 区域 | 尺寸 | 区域 | 尺寸 |
| --- | --- | --- | --- |
| 顶栏 | 57 | 时间轴卡 | 236 |
| 工具行 | 40（y=69） | 轨道 | 1542×184 |
| 工作区 | 475 | 标尺 / 字幕道 / 音轨 | 24 / 35 / 91 |
| 左栏 / 中栏 / 右栏 | 300 / 876 / 368 | 底部添加栏 | 132（y=854） |
| 播放器 | 814×458 | 时间轴工具行 / 输入框 | 26 / 70 |

随之对齐的行为：

- **播放头是连续时间**：按帧取整会吞掉每帧十几毫秒的推进量，播放时画面停在原处不动，所以量化只发生在写入文档时，播放头不量化。
- **画面时钟跟声音走**：有音频时用声卡时钟算进度，掉帧不会让画面落后于声音；纯字幕预览用起播锚点算，两者都不受掉帧影响。
- **当前句只看开始时间**：最后一条 `startMs ≤ 播放头` 的字幕就是当前句；落在字幕间隙或最后一句之后仍显示它（已入场完成），不回退到第一句、不淡出清屏。第 0 帧的入场进度为 0（以淡入为例，从全透明起）。
- **跳转会先停声**：点标尺、拖播放头、点字幕列表、上一条/下一条都走同一条跳转路径，先停音频再定位。
- **刻度基准定住**：打开时不足 5 秒按 5 秒铺，改卡片时长不缩放已有卡片；只有「⇲ 适配」按当前总时长铺满。主刻度按总长分档（1 秒 / 2 秒 / 5 秒 / 10 秒 / 30 秒）并随缩放反比收紧，次刻度在相邻主刻度之间切 5 份。
- **新字幕默认 1.2 秒一格**，长句用「⇥ 自动填充」或拖右端再调。
- **空轨道按 5 秒显示时间码**，播放器保持纯黑，不额外加占位文案。
- **深色主题同一套色值**（底 `#141413`、面 `#30302e`、分隔 `#3d3d3a`、强调 `#d97757`），字幕卡片固定蓝底蓝边，换主题不让它跟着变橙。
- **导出面板**按成品字段顺序排布（文件名 / 保存位置 / 编码器 / 分辨率 / 编码速度 / 画质 CRF / 编码加速 / 并行帧数），文件名默认按时间戳 `YYYYMMDD-HHmmss` 起，非法字符换下划线、没写后缀按容器补 `.mp4`。
- **画面按帧求值**：时间先换算成帧，入场用 `spring({damping:200})` 驱动旧版 `interpolate` 关键帧，30/60fps 同一帧的动效形状一致；帧率取工程文档，不读全局默认值。
- **瀑布流几何照旧版**：历史层按「上一行行高 + 16」向上累加，同字号同透明度、出画即裁；L 型拐角按每条字幕的 `moveAnimation` 整块转 90°，画面只留一个拐角；屏幕适配只按当前句取景，换句时 0.25s 平滑插值。
- **时间轴缩放是 1~20 倍率**：最左端显示「自动」，放大后显示「×N.N」；以播放头为锚点保持它在屏幕上的位置，「⇲ 适配」把倍率归位并把滚动条拉回开头。
- **拖动与裁剪有边界**：整体平移不许压到未移动卡片、不许推出 0 点；两端改时长夹在前一张尾部与后一张头部之间，最短一帧；位移吸附容差「至少一帧且 9 像素」，按住 Alt 临时关闭吸附。
- **框选按真实矩形取卡**：字幕卡与音频卡共用一套多选集合；Ctrl/Shift 点卡片只增减选中，单击卡片不移动播放头；选中不占撤销栈，裁剪后撤销一次就恢复原状。
- **三个开关照旧版**：同步开启时「⇥ 自动填充」变成「⇥ 消除缝隙」，拖音频块带着时间重叠的字幕一起走；「自动排序」持续生效，音频轨首尾相接并贴到 0 帧；「自动填充」只把前一条字幕的右端延长到下一条起点，不移动任何卡片、不动音频。
- **播放头跟随**：轨道溢出可视区时，播放头越过视口 8% / 92% 线就滚回中间；播放推进、手动定位与插入字幕后的跳转都跟随。
- **左栏与样式系统照旧版**：默认调色板 5 色（`#FFF4B5` 等）大写对齐成品；「随机分配」按当前调色板给每条字幕随机上色，「恢复默认」要点两下（第一下变「确认恢复」，4 秒不点自动退回）才会清掉新增与改过的颜色；导入 / 随机分配 / 语音转字幕 / 逐行应用都走同一套样式规则——字号在 `[minFontSize,maxFontSize]` 内随机、颜色从调色板随机取（空调色板退白）、旋转计划在拆分、合并、添加、导入与识别这五处生成字幕时按「随机移动」重算；「随机样式」开关关闭时所有字幕统一用全局入场动画（默认「打字机」），打开时给每条随机分配入场动画；背景图片按 `object-cover` 居中填满裁切（纯色 / 图片 / 透明三模式）；画布背景给黑、白、深海蓝、米杏四个预设，点预设时十六进制色值框与左侧拾色器一起跟着变。
- **音频轨与录音照旧版**：音频块标题带「源自 {源内偏移}」时间码，波形按整段音频时长把片段的源内区间映射到峰值数组，只画自己那一段；移动音频块只改 `startMs/endMs` 不动 `inMs`，裁剪左端与切分都让 `inMs` 同步推进，按片段重建音轨时源内位置连续。录音设置窗口给设备枚举、音量 0~200%（两端标「0% · 静音」/「200% · 增益」，可热调）、系统降噪 / 回声消除 / 自动增益 / 高通滤波四项排成一行（降噪、回声消除与高通默认开启，自动增益默认关闭；三项浏览器约束以 `ideal` 下发，切换前先停掉旧采集会话再重连，界面显示设备实际生效值；高通 80Hz，关闭时 20Hz 近似直通并可热调）、90px 实时波形与 RMS 电平表（fftSize 2048）。点「开始录制」另开录制窗口：时间轴式累积波形按录制时长自动分档（15 秒 → 30 秒 → 60 秒 → 2 分 → … → 30 分，之后每 5 分钟加一档）、时分秒计时、实时音量与设备信息；底部给「关闭窗口」（录制中禁用）、「暂停录制 ↔ 继续录制」、「停止录制 ↔ 开始录制」。停止只把片段列进下方列表（时长、录制时间），逐条给试听 / 暂停、删除、插入，点「插入」才写进音轨。新片段紧贴音轨最后一个片段末尾、不留空帧；与已有音源合并时先下混单声道再重采样到同一采样率，时长精确相加；已有音源为空时这次录音就是一条全新音轨。相邻两张音频卡的分界只按**各自还剩多少被剪掉的内容**给余量：往右推只在左卡右端还没回到源末尾时可用，往左推只在右卡左端还没回到源起点时可用；两张都没裁过（都是 100%）时分界推不动，切分出来的两段也推不动，绝不会把两段音频的内容拼到一起。
- **播放长度跟随轨道末尾**：刻度尺按旧版留出拖动余量（有音频时末尾再多 8%，最少 3 秒），播放与导出都以最后一张卡片的末尾为准；播放头、进度条、`setPlayhead` / `seekTo`、Home / End 与导出共用同一个末端值 `durationOf`，画面停在最后一帧、不画空白帧。
- **导出照成品**：质量档决定 CPU 预设（veryfast / medium / slow）与显卡预设（p3 / p5 / p7），有明确 CRF 就按它算、显卡用 CQ = CRF + 1，CRF 夹在 1..51（面板滑杆 14..30），并行帧数夹在 1..32、面板档位 自动 / 4 / 8 / 12 / 16 / 24，自动档由 ffmpeg 按机器核数自己决定；输出宽高按短边（1080 / 1440 / 2160）与画面比例推算并取偶数，竖屏 1080P 出 1080×1920，不是恒 1920×1080。选「显卡」但本机 ffmpeg 没编进对应编码器时直接报「当前 FFmpeg 不支持 xxx 硬件编码，请改用「自动」或「CPU 编码」。」；自动档先走显卡，失败安静回退 CPU 并照常出片（实测 5040×2160 超 NVENC 单边上限时会回退，成片标记为 CPU 编码）。音轨用 `-map 0:a:0?` 显式保留，AAC 192k。面板四态（设置 / 正在导出 / 导出完成 / 导出失败）与成品一致：标题随状态变、进度条下面写「编码器 · 分辨率 · 编码方式」与「已渲染 x / y 帧」、底部给成片体积与「打开输出目录 / 打开文件夹」，失败时给「重新设置」与「重试」。导出范围（I / O 打点）按区间平移字幕与音频片段、左边界被切掉多少就推进多少源内偏移。设置窗口 1080 宽、最小高 660，预览框按成片真实比例给尺寸（面积恒定，横屏竖屏都不变形），预览下方列出导出范围（全部帧 / 选定区间）、选中时长 / 总时长、导出帧数与跳过帧数、输出画面、编码参数、编码方式、并行线程、音轨；进行中窗口切为上下布局，预览在上，下方给进度、已渲染帧、平均速度（帧 / 秒）、实时倍率、已用计时、预计剩余、成片时长、输出规格、编码方式、导出范围与输出大小。
- **文件 IO 照成品**：字幕按扩展名或内容识别 SRT / VTT / TXT / JSON——BOM 与 CRLF 自动清理、编号错乱只认 `-->`、结束早于开始或负起点会被修正、VTT 跳过 `WEBVTT` 头与 `NOTE` 块并忽略 `align:start` 这类设置、`MM:SS.mmm` 省略小时的写法也认、JSON 同时接受 `startMs` 与 `start_ms`、没有时间码就按行拆句。生成端同样四种格式，往返解析时间不变；导出格式跟着工具行的下拉走，默认 SRT。旧版工程文件（`app` + `version` + `subtitles` + `settings` + `audio` + `audioSegments` + `exportRange`）可以直接载入：字幕文本、字号、字体、颜色、入场动效、移动方向、比例、位置、调色板、随机样式、旋转间隔、ASR 四项参数与导出范围全部还原，不认识的动效与方向退回安全值，空句丢弃；音频是文件路径，浏览器里读不到原文件，载入后提示重新载入。新版工程缺字段由 `migrate` 补齐，`schemaVersion` 不匹配会被拒绝。
- **快捷键照成品**：Ctrl/Cmd+T 加字幕、Ctrl/Cmd+B 在播放头切分、Ctrl/Cmd+E 合并选中字幕、Ctrl/Cmd+H 查找替换、Ctrl/Cmd+Z 撤销、Ctrl/Cmd+Shift+Z 或 Ctrl/Cmd+Y 重做、Delete 删除选中、Q / W 以播放头裁掉卡片前段 / 后段、I / O 打导出范围起终点、Esc 只清时间轴选中（弹出面板不响应 Esc，只能按面板上的关闭按钮关）、空格播放暂停；方向键左右按「Shift 5 秒 > Alt 1 秒 > Ctrl 5 帧 > 裸键 1 帧」步进，上下跳到前 / 后一张字幕或音频卡片的开头（两条轨合并去重），Home / End 到头尾。输入框里打字时全部让路，只有查找替换在输入框里也能唤起。
- **字幕列表编辑照成品**：顶部「编辑」开关关掉后每条只留一行文本，打开才有字号、颜色、入场、移动这些参数行。文本框里光标在中间按 Enter，按字数权重把这条拆成两条端点相接的字幕；光标在开头按 Backspace 与上一条合并、在末尾按 Delete 与下一条合并，文字首尾相接、时间横跨两条（含中间真空）。拆分与合并都算一次编辑结束，提交后就退出文本编辑状态（不再自动跳到下一条），点时间轴任意位置也直接退出编辑。查找替换面板给查找词、替换词、区分大小写与实时匹配处数，替换全部按字面匹配（正则元字符不生效）。播放时当前句加高亮并滚到列表正中，间隙与末尾不高亮。工具条的「关闭字幕」标签带来源名（导入文件名 / 「语音转字幕」/ 工程名）。
- **字幕列表控件与合并**：每条字幕的字号是 44px 窄数字框，可键入、滚轮微调，回车或失焦提交；选中两张以上字幕时，时间轴工具条上的「合并选中」图标按钮（Ctrl/Cmd+E）把文字首尾相接、时间横跨两条，选不足两张时按钮禁用。列表底部常驻显示「共 N 条 · 总长 X.Xs」。
- **分区尺寸**：左栏最小 / 默认宽 280px，可拖到 520px；右栏默认 304px，底部面板最小高 248px；双击任一分隔条把左、右、底三处尺寸一起恢复默认。布局偏好按版本键存本地，换工程保持。
- **悬浮提示与弹窗**：功能介绍、注释、用法一律走 `data-tip` 悬浮提示（document 级浮层，不受面板裁剪），状态数值仍常驻可见；弹出的设置 / 录音 / 识别 / 导出面板只能点面板上的关闭按钮关闭，点遮罩或按 Esc 都不关，任务进行中关闭按钮禁用。
- **点击画面播放 / 暂停**：点播放器画面里非控制条的区域就切换播放与暂停；底部控制条（进度条、播放 / 静音 / 全屏按钮）各管各的，点它们不会顺带切换播放。空工程没有内容时不起播。
- **打字机恒从左向右**：逐字露出时把首字钉在整句写完后的左端，后续字符往右延伸；右对齐字幕也从左往右冒字，动画结束整句右端仍落在原来的右对齐锚点上。
- **插入字幕按播放头分界**：播放头落在某张字幕卡内部时，旧卡截到播放头，剩下的时间段就是新字幕；落在两张卡之间（含恰好压在后卡起点）时，后一张卡从左侧剪掉一半，腾出的前半段连同空隙一起给新字幕；后面没有卡片时按字数预估时长向后占用；落在某卡最后一帧时视作接在这张卡之后，避免把刚加的卡压成碎片。任何一条轨道都过一遍首尾相接收口，卡片不许互相重叠。
- **输入框里也能用组合快捷键**：文本框编辑时 Ctrl / ⌘ 组合键照常生效（Ctrl+T 加字幕、Ctrl+B 切分、Ctrl+E 合并、Ctrl+Z / Y 撤销重做、Ctrl+H 查找替换），只有不带修饰键的裸键才让位给打字。
- **字体面板的字形工具行**：字体列表上方给一个示例文字输入框（输入什么，列表每行与悬停大预览就显示什么，回车或失焦后随工程保存），后跟加粗 / 倾斜 / 下划线 / 删除线四个图标按钮，默认只开启加粗。示例文字如实显示这些效果，画布渲染读的是同一份设置。
- **时间轴工具行右侧只报选中数量**：没选中显示「当前无选中卡片」，选中 N 张显示「已选中 N 张卡片」；裁剪、移动、分界这些操作结果只在后台记录，不占这块位置。
- **右上设置是齿轮图标**：点它打开设置面板，可改视频比例、帧率与导出分辨率。
- **框选与整组移动照成品**：从轨道任意空白处（字幕道、音轨道、空白带）起框，按真实矩形同时命中字幕卡与音频块；Ctrl/⌘/Shift 点卡片增减多选；拖任一已选中的卡片时保留整个选区，整组一起走，只有按在未选中的卡片上才把选区重置成单张。
- **字体目录**：五个系统字体（微软雅黑 / 黑体 / 宋体 / 楷体 / 仿宋）直接用系统字形；思源黑体、思源宋体、鸿蒙黑体、阿里巴巴普惠体 3.0、霞鹜文楷五款开源字体由安装脚本按 `install/deps.json` 从公共镜像下载到项目根 `fonts/`（官方 TTF / OTF 原件，逐个带 sha256 校验、多镜像回退与断点续传，也可以放进 `install/local/fonts/` 离线投放），按 `/fonts/<文件>` 注入 `@font-face`，换台机器也是真实字形（不是同一种回退字体）。清单文件名、`BUNDLED_FONTS` 与桌面壳 `BUNDLED_FONT_FILES` 三处由单测锁死一致；静态服务对 `.ttf` / `.otf` 返回对应 MIME。除系统字体外每行都有改名按钮，弹出面板可改中文名与英文名（只改显示，不动字体文件）。「导入本地字体」弹出面板：地址栏支持带双引号、正斜线、反斜线三种写法，右侧文件夹按钮拉起系统文件选择器并自动回填路径；中文名与英文名按文件名自动拆（中英混排各自归位，括号内容并入中文名），可手改，保存后字体文件拷进 `fonts/` 目录。鼠标指向某行整行高亮并弹出大预览框。桌面壳把目录存在用户数据目录（换工程、升级都不丢），浏览器里退回 localStorage；删除导入字体会连文件一起删掉。字体以 `@font-face` 注入并等加载完成再量字宽，否则字号会按回退字体算错；工程里用到的字体随字幕条目带走。打开字幕列表的「自定义字体」开关后，每条字幕可单独选字体。
- **语音转字幕照成品**：分句与成品 `asr-split` 同源——先按句末标点拆自然句，长句在 `[minChars,maxChars]` 区间按「句末标点 120 > 句中标点 95 > 连词 70+字数 > 语气词 45 > 中英边界 32 > 空格 24」打分选断点（同分取靠后），按字数权重分配时长、首段早出 80ms、末段晚收 80ms、帧对齐、端点相接不重叠、两三字碎片并回上条，标点一律不进字幕；同一份 SRT 与成品逐条一致（11 段文本 × 5 组参数 + 30 秒真实语音，85 项对拍全等）。识别走异步任务：提交后轮询真实阶段（提取音频 → 模型 / VAD / 逐段识别 → 分句 → 完成），进度条、段数、引擎日志与已用时间都来自引擎输出，不是假心跳；显卡后端（Vulkan）在本机 RTX 4060 上实测可用，阶段文案里的显卡名与「第几段 / 共几段」同样取自引擎日志（30 秒音频：显卡 1.3 秒 / CPU 12.5 秒）；四项参数（计算后端、单句最多字数、单句最长时长、语音分段长度）随工程保存，改完重开保持；结果先列前 10 条可展开，再整轨写入（替换已有字幕）并套用全局样式规则。界面在 5173、识别与转码服务在 5174，属于跨源调用，服务端只放行 `127.0.0.1` / `localhost` 来源（含 `OPTIONS` 预检），界面里的识别、转码与导出都走这一层。

以下几处是与成品不同的**形态**，行为口径一致：

| 分组 | 这里的做法 | 与成品的关系 |
| --- | --- | --- |
| 视频导出 | 浏览器逐帧驱动画布 + 采集音轨录成中间片，再交本地 ffmpeg 转 MP4；参数换算（质量档 → CPU 预设 / 显卡预设、CQ = CRF + 1、并行数夹到 1..32、输出宽高按短边与比例推算）统一在 `core/export-config` | 成品是一次编码出片，这里多一层中间片；成片时长、帧率、分辨率、音轨、回退逻辑与成品同口径 |
| 录音 / 语音转字幕 | 录音分「设置窗口 + 录制窗口」两态，识别是模态面板整屏三阶段 | 成品是独立窗口；设置窗口给设备 / 音量 / 四项开关 / 实时波形，录制窗口给累积波形、时分秒计时、暂停继续与片段列表，行为口径一致 |
| 波形 | 一次性解出峰值数组再按片段区间取用 | 成品在主进程流式解析；同一段音频的峰形与片段定位一致，差别只在超长文件的解码内存占用 |
| 桌面文件能力 | 目录选择、落盘、打开所在位置走 preload 白名单桥；浏览器里跑时退回下载到默认目录 | 成品只有桌面形态，这里同一套界面在两种环境都能用 |

新增模块继续按本文件第三节的规矩执行：补契约测试 → 补行为探针 → 挂进 `npm test` → 真跑那条执行路径。
